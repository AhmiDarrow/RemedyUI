# RemedyUI roadmap

Each milestone ends with something real running and tested. From M5 on, each also ends with a Remedy app moved onto the engine. Apps go smallest first, so each one proves a new part of the engine before the large ones depend on it. Every pack an app needs lands in that app's milestone or earlier. This file is the source of truth for milestone numbers; [APPS.md](APPS.md) refers to it.

Nothing is merged as a placeholder: a crate enters the workspace with its first real code and tests. Each milestone is judged by repeat runs of its scenario suites, its benchmarks against their targets, and its fuzzers.

## What is still open

The open items of every milestone in one place. Each milestone's section has the details.

- **M1:** `cargo vet` is not set up. GitHub Actions do not run on this repository, so the checks run locally before each merge.
- **M2:** per-platform IME protocols beyond TSF (each arrives with its bridge); the Arabic and CJK reference-shape test (CJK faces now ship in `fonts-cjk`; there is still no OFL Arabic fixture font); the FreeType comparison of hinted glyphs (a crispness check stands in).
- **M3:** AccessKit ships no schema validator, so the tests check roles, names, values and structure instead.
- **M4:** GPU windows present whole frames (wgpu has no partial presents). `bridge-macos` has not been run on a Mac.
- **M5:** the rest of `services-desktop` (see the M5 status). The tray, dialogs and single instance have not been run on macOS.
- **M6:** the macOS run of SecretFolder and Hearth, which needs a Mac.
- **M7:** FreeSpeak itself on RemedyUI on Windows, Linux, macOS and Android within its budgets, with the share pop-out as a real window, a Home built by a host and seen by a visitor on another platform, screen readers on every screen and the egui forks deleted. Not yet run on a Mac: `media-isolated`'s Seatbelt sandbox and `services-spell`'s `NSSpellChecker`. `media-video` takes frames in memory only; importing decoder textures without a copy is not built.
- **M8:** RemedyPDF, GuitarRemedy, VoiceRemedy and Portal on RemedyUI (app work; Alex's Craft Calc shipped on RemedyUI as `remedyui-v2.1.1`); what `media-playback` still lacks (listed under M8) and its macOS and Android runs; the 60 Hz pitch graph scene is not written yet.
- **M9:** the RemedyAI desktop on RemedyUI; an agent operating a FreeSpeak settings screen (waits on FreeSpeak). `embed-webview` reports `Unsupported` on macOS, Android and Wayland, and its Linux test runs only when asked (it needs X11 and WebKitGTK).
- **M10:** the Remedy apps on the frozen API for one release cycle, and publishing the 1.0 crates to crates.io. Reference budgets are held by the local gate, not CI.

## M2. Text

**Status:** built, with the open items listed below. Done:

- `remedy-ui-fonts`
- `remedy-ui-text` layout: fonts and fallback, rich spans, inline objects, wrapping and rewrapping, alignment, bidi runs, hit testing, carets, selection rects, words, visual movement

- glyph rasterization: skrifa hinting at the pixel size, an exact-area coverage rasterizer, grayscale and LCD with the FreeType filter
- the glyph atlas: shelf-packed pages that grow on demand, upload regions, page eviction under pressure

- the editing core: a rope buffer, grapheme-safe deletion and movement, Unicode word motion, selection, undo and redo grouped by word and pause, IME composition (preedit, commit, cancel)
- secrets: `SecretString`, which zeroes memory on growth, removal and drop and never prints, and `SecretEditor` with no undo

- deceptive text: invisible bidi and zero-width controls revealed (Trojan Source), UTS #39 confusable skeletons for look-alike names
- measured: 50,000 combining marks on one letter lay out in about 11 ms and a 1 MB single paragraph in about 150 ms (release build), both linear
- laziness inside one huge paragraph: a paragraph of 32 KB or more that wraps is laid out in pieces of about 8 KB, only those a view shows (and a window's height around them) and those its caret, selection and pointer reach, each piece starting at a line start the one before found (a checkpoint), with exactly the line breaks, glyphs, hit tests, carets and selections of a whole layout: seams are accepted only where two pieces lay out their shared lines alike, and bidi levels are those of the whole paragraph (left-to-right text before the first character needing bidi resolution has level 0 whatever follows; past it the whole paragraph's levels are resolved once, and after each edit, and pieces must match them, so right-to-left text pays that pass). Edits keep the pieces before and after them. Text elements and multi-line fields draw only the lines that show (so `doc-rich`'s paragraphs do too). `cargo bench -p remedy-ui-text --bench huge_paragraph`: first frame 1 MB about 400 ms before, 2.6 ms now; 10 MB 4.2 s, 7 ms; a keystroke 390 ms, 3 ms and 4.4 s, 5.5 ms; 1 MB of Arabic and Hebrew in English 1.5 s, 76 ms (the bidi pass); paragraphs under 32 KB as before. Tested against whole layout in Latin, mixed Arabic, Hebrew and English in both base directions, Arabic and Chinese
- reference shapes: fixed Arabic, Hebrew and Chinese paragraphs (joining, lam-alef, marks and points, numbers inside right-to-left text, full-width punctuation) shape to HarfBuzz's glyph ids, clusters, advances and mark offsets, their runs come out in the order GNU FriBidi's levels give, and they wrap where ICU4C allows (never before a full stop); the fixtures are Noto subsets of the test text under OFL, built with `tools/shape_references.py`

Open:

- Per-platform IME protocols. These arrive with each bridge (TSF in M4).
- The FreeType comparison of hinted glyphs. FreeType is C and not in the build, so the current check is crispness: hinted stems and crossbars land on whole pixels where unhinted ones do not.

**Crates:** `text` and `fonts` (the Remedy families, for tests and apps).

**Also built:** `remedy-ui-fonts-cjk` (the facade's `script-fonts` feature, on by default): Noto Sans SC and Noto Sans JP, Regular and Bold, as WOFF2 fallback faces (about 2 MB each, SIL OFL 1.1), so Chinese and Japanese text draws with no fonts installed. Each face is registered for its language, so a Japanese window draws unified Han characters such as 直 the Japanese way and a Chinese one the Chinese way, and kana take the Japanese face. Tested: every face parses and covers its language, and Han falls back by language. Korean and Traditional Chinese faces are not bundled; they draw through system font fallback where the system has them.

**Contents:**
- itemize, shape, break and position
- hinting and LCD rasterization, and the atlases' CPU side
- rich paragraphs with inline objects
- selection, and the editing core with undo and the zeroizing secret buffer
- IME through the headless runner's IME scripts

**Done when:**
- Latin, Arabic, Hebrew and CJK paragraphs lay out to match reference shapes
- hinted Remedy Sans UI glyphs match FreeType within tolerance
- selection spans paragraphs
- Zalgo and bidi-spoofing cases stay within frame time and render visibly

## M3. Layout, style, input and semantics

**Status:** built, with the open items listed at the end. `remedy-ui-layout` is built: flex, grid and block through taffy behind RemedyUI's own styles; a viewport root, so an auto-width root fills the window like a page body; inherited direction with logical insets mirrored for right to left; measured leaves; absolute and pixel-snapped rects; and the virtual list (estimates, Fenwick offsets, anchoring through inserts, removals and re-measures, stick-to-end, jump to any row).
`remedy-ui-motion` is built: cubic-Bézier easing with the standard curves, tweens, closed-form springs (stiffness and damping, or duration and bounce), retargeting that keeps position and velocity, animatable geometry and Oklab colors, the frame clock with presentation-time prediction and deadlines, and reduced motion. `remedy-ui-style` is built: typed themes (color roles, type scale, spacing, radii, motion, density), Dark Forest from RemedyAI's palette, derived tokens with Oklab-preserving contrast balancing (text AAA, muted and on-accent AA), state flags, and variant- and state-aware resolution cached by theme version. `remedy-ui-input` is built: the event model (pointers with kind, buttons, pressure and coalesced history; layout-aware keys with physical position and composing state; wheels), least-squares velocity, the gesture arena (tap, long press, pan, axis pans, platform slops), scroll axes with exponential fling decay and clamped or rubber-band edges, and the command table with scopes, enabled state, rebinding with conflict checks and platform chord labels. `remedy-ui-a11y` is built. It provides:
- RemedyUI's semantics model (roles, labels, values, numeric ranges, states, actions, set positions, live regions, hidden)
- incremental AccessKit tree updates that start only when a client connects
- merged rows with composed labels
- password inputs whose text is never exposed, not even through a merged parent

Open in M3:
- AccessKit ships no schema validator. The tests check that the produced updates have the expected roles, names, values and structure.
- Wiring these crates into the tree and frame (bindings that set semantics, styles and layout from elements) arrives with the first widgets in M5, which is where they first have callers.

**Crates:** `layout` (taffy behind RemedyUI types, pixel snapping, virtualization with anchoring), `style` (tokens, derived tokens, states, contrast helpers), `input` (event model, hit testing, gesture arena, scroll physics, focus, commands), `a11y` (semantics tree and incremental AccessKit updates), and `motion` (frame clock, transitions, springs). All of it is tested headless.

**Done when:**
- layout snapshots match references
- a virtual list keeps its anchor through inserts above it
- the gesture arena resolves nested pans
- the semantics tree passes AccessKit's schema checks for test scenes

## M4. Rendering, the compositor and Windows

**Status:** built (PRs #18-#27). `remedy-ui-paint` is built: display lists of rounded rects, borders, shadows, paths and strokes, gradients, glyph runs, images, clips, layers and transforms, with conservative bounds. `remedy-ui-render-cpu` is built: it draws display lists through vello_cpu at any device scale, with glyphs rasterized by RemedyUI's own hinted rasterizer, cached per size and subpixel bin, and composited in order so clips and layers apply. `remedy-ui-compositor` is built: layer trees shared through `Arc` and handed over in a single-slot mailbox; compositor-owned scroll offsets with fling and overscroll physics and wheel routing that hands an exhausted inner scroller outward; compositor-side offset, scale and opacity animations (reduced motion honored); 256/512-pixel tiles, rastered visible-first with a one-tile prefetch ring inside scroll containers, released on memory pressure or scale change; and per-layer damage in device pixels. `CpuCompositor` runs the plans, and its frames match direct rendering. `remedy-ui-render-gpu` is built: a backend ladder (D3D12/Vulkan/Metal, then GL, then a software adapter), display lists drawn through vello_gpu with the CPU renderer's own painter (glyphs and nearest-sampled images packed into RGBA atlas pages, filtered or large images in their own textures), compositor tiles in textures, a persistent pipeline cache where the driver has one (one unsafe call, in `ffi`), and device-loss recovery that rebuilds the device and re-rasters from the retained layer tree with no app code. Golden images match the CPU renderer (RTX 3080 on Vulkan: no pixel differs visibly at 1x or 2x). `remedy-ui-host` is built: the platform-neutral host model (windows, frames, input, input-method sessions, clipboard, timers, wake, settings, memory pressure, CPU presents with damage, native handles for GPU surfaces) that every bridge implements, with `Unsupported` for what a platform cannot do. `CompositorThread` runs the compositor on its own thread: scrolling keeps the display's rate while the UI thread is stalled, and an unchanged frame presents nothing (both tested). `remedy-ui-bridge-headless` is built: the host in memory with a scripted clock, input, IME, clipboard, timers and wakes; presents copy only their damage, so tests prove damage is complete. `remedy-ui-bridge-winit` is built: one host implementation for every desktop winit serves (windows, pointer, touch, wheel and keys, IME sessions with caret area and private-input purpose, frames on redraw, timers, cross-thread wakes, softbuffer presents writing only damage when the buffer holds the previous frame, native handles for GPU surfaces); platform bridges add only `PlatformHooks`. `remedy-ui-bridge-windows` is built on it: the Win32 clipboard (sensitive copies excluded from monitors, clipboard history and cloud sync), capture protection, and real system settings; a real-window test runs the whole contract. GPU frames present to windows: `GpuSurface` picks an 8-bit RGBA/BGRA swapchain format with its own pipelines, paces to vsync, handles occluded, outdated and lost swapchains, and rebuilds itself on the new device after a device loss (tested on a real window through a resize and a forced loss). GPU validation errors are recorded rather than panicking. GPU windows on D3D12 and Vulkan present only their damage through swapchains of RemedyUI's own on wgpu's device (DXGI dirty rectangles, `VK_KHR_incremental_present`), on unmodified wgpu; the CPU path presents damage too. `remedy-ui-bridge-macos` (AppKit pasteboard with concealed/transient markers for sensitive copies, `NSWindowSharingNone`, appearance, accent, contrast, motion, transparency, locale, double-click interval) and `remedy-ui-bridge-linux` (one crate for Wayland and X11: arboard clipboard with the password-manager hint, XDG portal settings over zbus, honest `Unsupported` for capture protection) are built on the shared core and lint clean when cross-compiled for macOS and Linux here; they still need a run on those machines. LCD text draws on both renderers (two passes per run: a multiply by `1 - coverage` per channel, then the color added per channel; exact over opaque pixels, grayscale inside groups), and the GPU matches the CPU. TSF is built: a safe UTF-16 text store (selection, composition, reconversion, surrounding text, edits turned into input-method events) behind a COM `ITextStoreACP` with TSF's lock protocol, one document per window, password fields with no input method; tested by driving the COM store exactly as TSF does and by TSF connecting to it on a real window. No pipeline or shader is created after start-up (wgpu resource counters, tested). Every M4 done-when item has a test. Showing old tiles scaled while new ones raster during a zoom was built with `doc-pages` in M8, its first user.

**Crates:** `paint`, `compositor`, `render-gpu`, `render-cpu`, `bridge-windows` (with TSF), `bridge-headless`.

**Contents:**
- paint chunks, layers, tiles and the commit
- compositor-side scrolling and animation
- damage-only presenting
- the start-up pipeline set, the backend ladder and device-loss recovery

**Done when:**
- golden images match between the GPU and CPU renderers
- a forced device loss recovers with no app code
- scrolling keeps the display's rate while the UI thread is artificially stalled
- an unchanged frame presents nothing
- no shader compiles after start-up in a recorded session

An app's `#[preview]` functions are listed for rendering by path. Live apps are operated over the agents listener's token-gated loopback protocol, with "asking the person" outcomes waited for and reported; remote devtools likewise. Paths stay inside the workspace the person names.
- `remedy-templates` (L7): the app templates (basic, tray, multi-window, document, android), moved out of `cargo-remedy` so `cargo remedy new` and the tools' `new_app` make the same app without either running the other.
- `remedy-mcp` (L7): the Model Context Protocol server over the official Rust SDK (`rmcp`), stdio or streamable HTTP on loopback behind a bearer token; each group a `ToolGroup`, composed by `Server::builder()` at compile time (features) and run time (`--tools docs,live`); the guides as resources, prompts for building a screen and operating an app. See [MCP.md](MCP.md).
- `cargo remedy` gained every tool as a command (`docs`, `widgets`, `rui`, `preview`, `audit`, `test`, `budgets`, `app`, `devtools`), readable by default and `--json` for scripts. See [CLI.md](CLI.md).
- Tested end to end: a scripted MCP client drives the server as a child process (docs, markup, a real preview's pixels, tests, new apps, a window operated under read-only, acting and confirming grants with a wrong token refused, its devtools), the HTTP transport's token, run-time tool selection and a docs-only build; the commands run as subprocesses against the same fixture app and window.

**Status:** in progress. Built before the freeze, the parts of the design the code lacked:
- **Context:** `provide_context`/`use_context` over the reactive owner chain (`Owner`, scope context), and `El::provide`, `El::use_context`, `El::child_with` over the element tree. Windows' content is built with the app and its persisted-state store provided.
- **Control flow:** `show(ui, cond, build)` with a fallback and enter and exit transitions (leaving content stays inert until its exit ends); `catch_errors(ui, fallback, child)` containing panics in building, handlers, bindings, effects and painters, with the element path, source location and phase, a retry, the window's failure list and an error hook (effects reach boundaries through a reactive `ErrorSink` and the runtime's panic handlers; the tree hands its failures to the view); `suspense(ui, placeholder, child)` with a delay before the placeholder and a minimum time shown.
- **Resources:** `Resource` fetches off the UI thread on an `Executor` (the shared `WorkerPool` unless one is provided as context), cancels on key change and disposal, and registers with the nearest `Suspense` when read. No async runtime.
- **Persisted signals:** `Signal::persist("key")` (reactive feature `persist`, on in the facade) in a `PersistStore`: debounced, atomic JSON writes off the UI thread, versions and migrations, files of newer versions left alone; `App::persist_store` is `<data>/state`, flushed on quit.
- **Properties:** `IntoProp` (a value, signal, memo or closure) for `text`, `disabled`, `variant`, `semantics`, `style` and the core widgets' labels; `style_dyn`, `disabled_dyn` and `semantics_dyn` are gone, `text_dyn` stays deprecated because FreeSpeak uses it.
- **Typed tokens:** `Space`, `Radius`, `TextRole`, `ColorRole`, `Dp`, `Pad` and token `Style` patches, taken by `gap`, `width`, `height`, `padding` and `style`, resolved through the theme and again on each theme change.
- **Previews:** `#[preview(...)]` (themes, locales, sizes, text scales) makes a `PreviewSpec` and a golden-image test; `#[previews]` lists a module's previews for the gallery.
- **Motion:** `El::animate`/`animate_then`/`animate_style` on the frame clock (springs and tweens from `remedy-ui-motion`, interruption from the current value and velocity, instant under reduced motion), `remedy_ui::motion`, and `PaintCx::time` and `reduced_motion` so painters animate without timers (the spinner and indeterminate progress now do).
- **Lists:** `for_each`, `list` and `virtual_list` take a `SignalVec` and apply its operations (one row per push or insert, nothing built for moves and removals, rows built in scopes of their own); list rows give screen readers a merged name, place in set and selection; tree rows select on an assistive Click and open and close through Expand and Collapse (`El::on_accessibility_action`).
- **Keyed transitions, failures page, element ownership:** `for_each_with` plays enter and exit transitions and glides staying rows to new places (`El::flip`, FLIP), instant under reduced motion; the inspector's Failures page lists caught failures (message, phase, element path, source location) with Retry for boundaries still failed and Clear (`Ui::clear_failures`, `retry_failure`, `is_failed`); elements' scopes are owned by nothing (`Scope::detached`, reading context where they were built) and their bindings by their scope (`Effect::new_in`), so content built while a binding runs keeps its bindings when that binding runs again. An audit of the widget packs found their bindings either clear and rebuild what they build, or already build in scopes of their own (board reactions, lists, `show`, boundaries); the fix covers app code that keeps content built in a binding, such as a page pushed onto a `NavStack` from a route binding.
- **Smaller fixes:** every OSC 52 request in one sync reaches the app in order; terminal text exports leave out trailing blank rows; `thumbnails` has its own width and `page_view` never takes its height from its pages; pseudo-locales reach screen readers and the inspector.
